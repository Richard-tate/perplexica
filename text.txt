  Step-by-Step: The Researcher Loop

  Iteration 1 — The LLM receives the researcher prompt + available tools and decides what to do:

  Messages sent to MiniMax:
    system: "You are a research assistant. Available tools: web_search,
             academic_search, social_search, scrape_url, done..."
    user:   "Explain the Repository Pattern in Laravel. Include:
             1. What problem it solves  2. How it differs from..."

  MiniMax responds with tool calls (via Anthropic SDK format):

  {
    "tool_calls": [
      {
        "id": "tc_abc123",
        "name": "web_search",
        "arguments": {
          "queries": [
            "Repository Pattern Laravel what problem it solves",
            "Laravel Repository Pattern vs Service Layer differences",
            "Laravel Controller Service Repository Model code example"
          ]
        }
      }
    ]
  }

  Tool Execution — All 3 queries hit SearxNG in parallel:

  searchSearxng("Repository Pattern Laravel what problem it solves")
    → GET http://localhost:8080/search?format=json&q=Repository+Pattern+Laravel...
    → returns { results: [{title, url, content}, ...], suggestions: [...] }

  Results are converted to Chunk[] objects and fed back to the LLM:

  Messages now:
    system:    researcher prompt
    user:      original query
    assistant: { tool_calls: [{ id: "tc_abc123", name: "web_search", ... }] }
    tool:      { id: "tc_abc123", content: '{"type":"search_results","results":[
                  {"content":"The Repository Pattern abstracts data access...",
                   "metadata":{"title":"...","url":"https://..."}}
                ]}' }

  Iteration 2 — MiniMax sees the search results and decides: enough info? or search more?

  - If enough → calls done tool → loop exits
  - If not → calls web_search again with refined queries, or scrape_url to read a specific article in depth

  After the Loop: Answer Generation

          ┌───────────────────────┐
          │   3. WRITER           │  Separate LLM call (no tools)
          │   (streamText)        │  Gets search results as XML context
          └───────────┬───────────┘
                      ↓
                Streamed response

  The Writer prompt wraps all search results as context:

  <search_results>
    <result index=1 title="Repository Pattern in Laravel">
      The Repository Pattern abstracts data access...
    </result>
    <result index=2 title="Service Layer vs Repository">
      While a Service Layer handles business logic...
    </result>
  </search_results>

  The LLM then generates the final answer with [1], [2] citations, streamed back to the UI in real-time.

  Key Points for MiniMax Integration

  ┌────────────┬─────────────────────────┬────────────────────────────────────────┐
  │    Step    │     LLM Method Used     │             Why It Matters             │
  ├────────────┼─────────────────────────┼────────────────────────────────────────┤
  │ Classifier │ generateObject()        │ Must return valid structured JSON      │
  ├────────────┼─────────────────────────┼────────────────────────────────────────┤
  │ Researcher │ streamText() with tools │ Must handle tool calls + IDs correctly │
  ├────────────┼─────────────────────────┼────────────────────────────────────────┤
  │ Writer     │ streamText() no tools   │ Basic streaming, straightforward       │
  └────────────┴─────────────────────────┴────────────────────────────────────────┘

  The Researcher step is the critical one — this is where multi-turn tool calling happens. The LLM must:
  1. Decide which tools to call from the available set
  2. Return properly formatted tool calls with valid IDs
  3. Accept tool results back and reason about them
  4. Know when to call done to stop

  This is exactly why M2.5's 76.8% BFCL multi-turn score matters — the entire search quality depends on the LLM making good tool-calling decisions   
  across multiple rounds.
